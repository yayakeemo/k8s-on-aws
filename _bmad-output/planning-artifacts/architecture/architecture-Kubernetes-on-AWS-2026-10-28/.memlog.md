- (decision) Paradigm: layered stacks with one-way dependency (bootstrap -> persistent -> ephemeral/core -> ephemeral/gitops -> in-cluster GitOps) + pull-based GitOps reconciliation in-cluster. Prevents: lower layer reading upper, cycles that break Teardown.
- (decision) Terraform roots = 4 (bootstrap, persistent, ephemeral/core, ephemeral/gitops), one S3 state key each, S3 native lockfile (no DynamoDB). Prevents: kubernetes/helm providers in same root as EKS creation (destroy breaks) and mixed persistent/ephemeral state.
- (decision) Cross-root handoff: upstream roots publish outputs to SSM Parameter Store /k8s-on-aws/<layer>/<name>; downstream reads via data source. No terraform_remote_state, no hardcoded ARNs. Prevents: implicit coupling + full-state read access.
- (decision) Terraform->Argo CD handoff only via GitOps Bridge: ephemeral/gitops writes Argo CD cluster-secret annotations (cluster name, vpc id, region, cert arn, AMP url, hostname, session_id); ApplicationSets template from them. Prevents: per-rebuild values hardcoded in Git.
- (decision) Ownership boundary: AWS-side resources (incl IAM roles + Pod Identity associations for controllers) in Terraform; everything inside k8s (controllers, app, CRDs) in Argo CD. Only exception: Argo CD itself + root app installed by ephemeral/gitops.
- (decision) Session state: SSM param /k8s-on-aws/session/active holds session_id (format YYYYMMDDTHHMMZ) or 'none'; set by Rebuild at start, cleared by Teardown at end. Ephemeral apply-on-merge reads it; 'none' => plan only. All ephemeral-mutating workflows share one GH Actions concurrency group. Prevents: merge-apply during teardown, timestamp-driven diffs.
- (decision) Tagging: provider default_tags + controller default tags: Project=k8s-on-aws, Layer=bootstrap|persistent|ephemeral, Session=<id> (ephemeral). Post-Teardown check = tag query + type sweep of billable types vs persistent allowlist. Prevents: untracked controller resources escaping check.
- (decision) Teardown order fixed: set session draining -> final snapshot via destroy of RDS w/ final_snapshot_identifier k8s-on-aws-final-<session_id> -> delete workload apps -> delete Gateway/HTTPRoutes, wait LBs + DNS records gone -> remove controllers -> destroy ephemeral/gitops -> destroy ephemeral/core -> prune snapshots to 5 -> post-teardown check -> session=none. Actually: drain k8s first, then destroy core (RDS final snapshot happens in core destroy).
- (decision) No PersistentVolumeClaims in v1; all durable state in RDS/AMP/CloudWatch Logs/S3. EBS CSI not installed. Prevents: orphaned EBS volumes at teardown.
- (decision) RDS restore: pipeline resolves latest k8s-on-aws-final-* snapshot via AWS CLI and passes var restore_snapshot_id (empty => fresh DB). Terraform never looks up snapshots; snapshot_identifier under ignore_changes. restore_mode input supports snapshot|pitr-from-retained-backup|empty for FR-22.

- (decision) Edge chain: Route53 -> ALB (LBC Gateway API, ACM cert per Rebuild) -> oauth2-proxy (reverse proxy, Cognito OIDC) -> app. Only oauth2-proxy can reach app pods (netpol).
